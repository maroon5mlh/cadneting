# CAD 排样插件（钣金激光切割 · 块级共边排版）

AutoCAD 插件：选中一批闭合图形块 → 提取轮廓 → 归并计数 → 排样 → 按板平铺回写。

**全程不炸开块**：只读遍历块定义得到轮廓，排完只改 `BlockReference` 的位置和旋转。

## 当前能力

| 命令            | 作用                                    |
| ------------- | ------------------------------------- |
| `NESTPANEL`   | 打开停靠面板（参数 + 方案对比 + 结果）                |
| `NESTAUTO`    | 面板主按钮：选块 → 提取 → **多方案对比** → 点插入点摆放      |
| `NESTAPPLYPLAN` | 应用面板里当前选中的方案（不重新排样，只改块位置）           |
| `NESTEXTRACT` | 只提取，导出 `nestjob_*.json`（用于核对品种和件数）    |
| `NESTRUN`     | 读任务 JSON → 排样 → 点插入点摆放 → 写 `.result.json` |
| `NESTAPPLY`   | 只读结果 JSON → 点插入点摆放（重放已有方案）           |
| `NESTDIAG`    | 自检：加载的是哪个 dll、依赖是否齐、面板是否创建成功          |

**不包含**（按确认的需求，明确不做）：割缝补偿、引线、穿孔点、微连/桥接、刀路生成。

## 插入点：排完用鼠标点位置

摆放不再固定落在原点，而是先要一个插入点：

- 命令一执行，光标上就挂着一个**实际尺寸的板框**（第一张板）跟着走，点一下即定；
- 插入点 = 第一张板的**左下角**，其余板按「板宽 + 300 mm」向右排开；
- **回车** = 沿用上次的插入点 —— 换方案重排时原地覆盖，不用重新点；
- **ESC** = 不摆放，方案保留在面板里，稍后点「应用选中」再来。

实现是 `EntityJig`（`UI/InsertPointJig.cs`）：拖动只更新 4 个顶点、只预览第一张板框，
所以几百件的批量也不掉帧。jig 采到的 UCS 点会先转成 WCS，UCS 与 WCS 不一致时板框不会跟着歪。

命令行的「上次插入点 (x, y)」就是当前会沿用的位置；首次运行是 (0, 0)。

### 分批排样：各批板框互不影响

板框画在 `NEST_SHEET` 图层。每次摆放重画之前，只删「框里装着本批零件」的那些旧框
（换方案、原地重排时刷新），**别的批次的框一律保留** —— 所以可以在同一张图上接着排
第二、第三批，之前排好的料和它的板框都还在。

判据是**两级**的：

1. 每个板框都往 XData（`CADNESTING_SHEET`）写一枚批次指纹 —— 本批零件句柄集合的哈希。
   重画前只清「指纹等于本批」的框，所以换方案、同一批原地重排都会刷新，
   而另一批零件的框绝不会被碰（哪怕新件就堆在旧框里）。指纹用句柄算，不看块位置，
   零件被挪动过也认得出。
2. 没有指纹的框（旧版本插件画的）退化成几何判断：框里装着本批的块才清。
   这一条只为兼容升级前留下的框，跑过一次之后就都用指纹了。

## 排样引擎

`Nesting.Core/Solvers/` 里是自研引擎，不依赖任何外部进程或第三方库。

**算法：MaxRects 自由矩形装箱 + 多启发式择优。**

选择理由：激光切割没有通切约束，MaxRects 比 Guillotine 排得更紧（Guillotine 要求每刀贯穿整板）。  
零件按**包围盒**参与碰撞判定——轮廓必然 ⊆ 包围盒，所以结果**永远不会重叠**，  
只是轮廓凹陷处会浪费一点空间。

判定依据是**包围盒填充率**（`NetArea / 包围盒面积`）：

- ≥ 97%：基本是矩形，包围盒排样损失 < 1%，毫秒级出结果
- < 97%：L 形/U 形，包围盒会明显浪费，引擎会在结果 `Warnings` 里点名这些品种

实测你那批封板件的填充率是 **99.75% / 99.55%**（带角部台阶的矩形），属于第一类。

求解流程：4 种排序（面积/长边/周长/高度降序）× 3 种插入启发式（最贴短边/最贴面积/左下优先）  
= 12 次尝试，取「张数最少 → 板材总面积最小」的那个解。

### 多规格时的大板优先

勾了多种板时，**开新板先挑「能装下的最大规格」**：大板被排满，装不下的（超幅件）  
才往下一个规格走。这是面板上的「大板优先」开关，默认开启。

关掉它会退回「能装下的最小板」：能进 2250 的件绝不占 2440，用料面积更省，  
但张数通常更多 —— 200 件 1000×600 是「4 张 3050」vs「7 张 2250」的区别。

这个顺序是**策略**，不是给引擎参考的偏好：选定之后引擎不会再用"张数最少"  
把它换回另一种板型，否则用户勾了「大板优先」却拿到一版小板方案，看起来就是开关没反应。

**两个口径会打架，所以两个都报**：张数最少的解往往用更大的板，用料面积反而略多  
（压测：56 张 3050 = 208.4 m² vs 69 张 2440 = 205.4 m²）。默认按「张数最少」，  
结果里会附带另一个口径的数字。想改成省料优先，把任务 JSON 里的  
`Settings.Objective` 设为 `"area"` 即可。

## 方案对比

一次排样会同时算出几个候选方案，摆进面板的「方案对比」表里，默认应用推荐的，
其余可以点一行就换过去。**排样没有唯一解，"最优"取决于目的**，与其替用户决定，不如把候选摆出来。

| 候选 | 含义 | 会改工艺吗 |
|---|---|---|
| **基准** | 完全按面板设置 | 否 |
| **仅 1220x2440 / 2250 / 3050** | 库存只有这一种板时的现实方案 | 否 |
| **省料优先** | 同样这批板，目标换成用料面积最小 | 否 |
| **小板优先** | 大板优先的对照：能进小板的件不占大板（仅勾了多种规格时出现） | 否 |
| **全转 90°** | 连有纹向要求的件也放开旋转（仅当面板禁止旋转时出现） | **是**，橙色标注 |

实测一组 117 件的封板料：

```
A ★ 基准           19 张   67.2%   70.70 m²  1220x3050×19
B   仅 1220x2440   24 张   66.5%   71.44 m²  1220x2440×24
C   仅 1220x2250   27 张   64.1%   74.11 m²  1220x2250×27
D   全转 90°       16 张   79.8%   59.54 m²  1220x3050×16   ← 改工艺前提
```

几个实现上的决定：

- **同解会合并**。基准本来就选了「仅 3050」的话，那两行不重复显示，合并成
  `(同解:仅 1220x3050)`。判据是「张数 + 规格构成 + 摆法」，只比张数会把不同规格的
  两个真方案错误合并（料钱和换板次数都不一样）。
- **推荐只在"不改工艺"的方案里选**。全转 90° 通常张数最少、利用率最高，
  但它动的是纹向/折弯方向，这类事不能由软件替车间拍板。
- **换方案是绝对定位，不是增量移动**。块按包围盒重新锚定，反复点「应用选中」不会累积偏移；
  上一版画的板框会被清掉（只删本插件画的那种：`NEST_SHEET` 层、闭合、4 个顶点），
  不会误删你自己放的东西。

## 编译

```cmd
git clone git@github.com:maroon5mlh/cadneting.git
cd cadneting

build.cmd
```

`build.cmd` 会自动从注册表识别 AutoCAD 安装目录（也支持 `ACAD_DIR` 环境变量），  
输出到 `build\<时间戳>\`，打印需要 NETLOAD 的完整路径，并把两个 dll 同步进 `CadNesting.bundle\Contents\Windows\`。

**为什么要带时间戳**：NETLOAD 过的 dll 会被 AutoCAD 进程锁住直到关闭 CAD，  
直接覆盖 `dist\` 会报 `MSB3021 文件被占用`。每次输出到新目录就不用等解锁。

自动识别失败（多版本共存、绿色安装、装在其他盘）时，任选一种方式指定：

```cmd
:: 方式一：命令行传参
build.cmd "C:\Program Files\Autodesk\AutoCAD 2026"

:: 方式二：本机配置文件（已被 .gitignore 排除，不会进仓库）
::   新建 src\Nesting.AutoCAD\AcadDir.local.props，内容：
::   <Project><PropertyGroup><AcadDir>D:\CAD2017\AutoCAD 2027</AcadDir></PropertyGroup></Project>

:: 方式三：环境变量
set ACAD_DIR=D:\CAD2017\AutoCAD 2027 && build.cmd

:: 方式四：直接用 dotnet（需方式二或三已配置）
dotnet build src/Nesting.AutoCAD/Nesting.AutoCAD.csproj -c Release -p:AcadDir="你的AutoCAD目录"
```

找不到 `acmgd.dll` 时构建会直接报一句人话，而不是抛一串 HintPath 警告。

## 冒烟测试（不需要 AutoCAD）

```bash
dotnet run --project tests/SmokeTest -c Release
dotnet run --project tests/SmokeTest -c Release -- debug   # 打印重叠诊断
```

覆盖（97 项断言）：

- 凸度圆弧采样精度（弦高控制）、正负 bulge 方向
- 品种归并计数、JSON 往返、中文块名编码
- **实图排样**：自动读取桌面上最新的 `nestjob_*.json` 跑一遍，张数按面积下限校验
- **压测**：428 件合零件，校验全部落位、板内不越界、**零件之间零重叠**、**避开留边**
- **不旋转代价**：同一批件关掉旋转再跑一遍，量化"少转 90° 要多几张板"
- **规格择优**：三规格必须比"只用最小板"张数更少（锁住逐件贪心把大板饿死的 bug）
- **方案对比**：每个候选都单独过几何校验（越界/重叠/留边）、无重复签名、
  推荐项唯一且不改工艺前提、省料方案用料不多于基准、全转方案张数不多于基准
- **留边**：四边都守（只查左边会漏掉"贴右边切不出来"）
- **关键字旋转**：全局关掉旋转时，命中关键字的件仍必须转 90°；未命中的必须报错而不是悄悄转
- **文字句柄**：按实例传递、空串不产生句柄、不串位
- **参数持久化**：默认值、往返不丢（含间距 0 这种"零值"）、损坏文件退化成默认值

## 使用

1. `NESTPANEL` 打开面板
2. 勾选板材规格（默认 `1220x2440` / `1220x2250` / `1220x3050`，可增删改），填四个参数：
   - **间距**：零件之间净距，默认 **0**（块级共边直接贴边排；要割缝补偿或防热变形再调大）
   - **留边**：零件到板四边的距离，默认 **5mm**。四边等距，因为板边不整齐、  
     边缘吸附和夹具都需要余量；只留左下两边会出现"贴着上/右边的件切不出来"
   - **允许旋转 90°**：默认**不勾选**。有纹向/折弯方向的件转了就是废料
   - **强制可转**：块名含任一关键字即允许 90° 旋转，**不受「允许旋转 90°」全局开关影响**。  
     默认 `顶包边、底框、中横框`，用顿号/逗号/空格分隔
   - **排除块**：块名含任一关键字的块**不参与排样**（也不移动）。用来挡住折弯标记、
     压线、孔位标记这类辅助块 —— 见下面「板没排满」一节。留空 = 全部参与
3. 「文字跟随块」默认勾上：排样时块旁边的标注文字跟着一起移动、一起转
4. 点「选择图形并对比方案」，框选块参照
5. **「方案对比」表**列出几个候选（带 ★ 的是推荐），默认应用推荐方案；
   点其它行会预览该方案的结果，再点「应用选中」换过去
6. 结果表格显示每张板的件数、利用率和**余料**；模型空间里按板平铺（板间距 300mm）

### 某一批板"没排满就换下一张"怎么查

结果表里的**余料**列就是答案的一半：它算的是"这张板上还剩多大的空地"（板面积 − 零件包围盒），  
利用率低但余料小，说明是异形件的凹陷；余料很大，说明是真没排满。

真没排满的最常见原因**不在引擎，而在选料**：图里的折弯标记、压线、孔位标记被当成零件框进来了。  
这类块面积很小（比如 `29x2075` 只有 0.06 m²），但装箱时必须占掉**一整列 2075 的高度**，  
顺序上又排在最后，于是把最后一张板顶出来 —— 实测一批 26 件的料混进 3 个标记块，  
从 **4 张 2440** 变成 **5 张**，最后那张只放得下 2 件小料（余料 2.78 m²）。

处理办法：在面板「排除块」里填块名关键字（例如 `BEND_MARK`），这批料立刻回到 4 张。  
排样结果里会明确写出"按排除块跳过了哪几个块、共几件"，不会悄悄少排。

## 参数持久化

面板上的一切**改完即存**，下次打开 AutoCAD 自动恢复：板材规格（含增删的行和勾选状态）、  
间距、留边、旋转开关、大板优先、文字跟随、强制可转关键字、排除块关键字。

配置文件：`%AppData%\CadNesting\panel-settings.json`

**为什么不放在插件目录**：插件在 Program Files / bundle 下，普通用户没有写权限，  
而且升级或重装插件会把它冲掉。

**为什么读写都吞异常**：参数丢了顶多下次重填一遍，但磁盘只读或文件被占用时  
把异常抛到 UI 线程，面板会直接崩掉。失败原因记在 `PanelSettings.LastError`，  
`NESTDIAG` 会打印出来，同时显示配置文件路径。

写盘走「先写 `.tmp` 再 `File.Replace`」，断电或进程被杀不会留下半截 JSON；  
文件损坏时自动退回面板默认值，不会让面板打不开。

## 三处行为细节（容易踩的坑都在这）

**留边不是排完再加偏移。** 可用区域的自由矩形从 `(margin, margin)` 起、尺寸减 `2*margin`，  
所以引擎输出的 `X/Y` 天然已经含留边。事后加偏移会在板材尺寸、利用率、越界判断三处各埋一个坑。

**旋转是三层判定，顺序不能反**：

```
零件自身允许(纹向/折弯硬约束)  →  全局开关  →  关键字白名单
                                      ↑              ↑
                                  批量关掉      命中即放行，覆盖全局
```

关键字用「包含」匹配，所以 `顶包边-2611060` 能命中 `顶包边`。  
**如果一条都没命中，而全局开关是关的，引擎会在 `Warnings` 里明确报出来** ——  
否则表现是"排得通、但比预期多一两张板"，几乎不可能联想到关键字写错了。

**文字跟随靠几何推断，不靠链接。** XK 命令把文字写成模型空间里独立的 `DBText`/`MTEXT`，  
位置取块**包围盒中心**，和块之间没有任何分组、反应器或扩展数据。  
所以插件按"文字插入点落在块的包围盒内 → 归给中心最近的那个块"来关联，  
一个块可以有多条文字（名称 + 数量），全部跟随。

关联结果会在命令行打印：`跟随文字：关联 26 条，覆盖 26 件`。  
**如果这个数字是 0，说明文字不在块的包围盒内**（例如放在了块外面一段距离），  
把文字 `MOVE` 进块范围再跑，或者告诉我实际偏移量，我改成按距离匹配。

文字跟着块转 90° 后如果角度落在 (90°, 270°)，会被自动减 180° 纠正回正方向  
——否则块转 90° 时原本竖排的文字会变成倒字，打印出来是反的。

## 排障

**面板不显示** → 先跑 `NESTDIAG`，看程序集路径是不是当前这次编译的产物、`Nesting.Core.dll` 是否在同一目录。  
若面板被折叠成了侧边的竖排标签，点一下那个标签即可展开。

**必须重启 AutoCAD 才能换新 dll**。NETLOAD 过的程序集在 AutoCAD 进程内无法卸载，  
同名 dll 再次 NETLOAD 会沿用旧的那一份，表现为「改了代码但行为没变」。这也是构建输出带时间戳的原因。

**`eKeyNotFound`**：板框图层 `NEST_SHEET` 不存在。已在代码里按需创建图层，  
不再依赖图纸预先存在该图层（早期版本在这里抛异常会导致整个事务回滚，一件都摆不上）。

**`eOnLockedLayer` / 摆放失败 N 件**：块所在图层被锁定。命令会跳过失败的块并继续，  
解锁对应图层后重跑即可。

## 面板与 CAD 线程的关系（重要）

面板是**模态外**的，从按钮事件里直接调用 `Editor` / `Database` 会抛 `eInvalidContext` 或随机崩溃。

做法：按钮只发一条命令

```csharp
doc.SendStringToExecute("NESTAUTO ", true, false, false);
```

执行权回到文档上下文后再操作数据库。这条链路上没有任何跨线程调用。

```json
  "Parts": [
    {
      "Id": "P001",
      "BlockName": "排版-下前封板0",
      "Outer": { "Points": [ { "X": 0, "Y": 0 }, { "X": 1200, "Y": 0 } ] },
      "Holes": [],
      "NetArea": 480000,
      "Width": 1200,
      "Height": 400,
      "AllowRotate90": true,
      "Quantity": 12,
      "Handles": ["2A1", "2A2"],
      "TextHandles": ["3B4,3B5", "3B6"]
    }
  ],

    "SpacingMm": 0,
    "MarginMm": 5,

    "SheetPreferLarge": true,
    "TimeLimitSec": 60,
    "Objective": "sheets",
    "FlattenTolerance": 0.1
  }
}
```

- `Outer.Points` 已归一化到「包围盒左下角为原点」，首尾点不重复
- `Handles` 与 `Quantity` 一一对应，是回写时的定位依据
- `TextHandles` 与 `Handles` **严格同序**，每项可能含多个句柄（逗号分隔），空串表示该件没有文字
- `AllowRotate90` 可按品种单独关闭（有纹理/折弯方向要求的件）
- `MarginMm` 留边，`RotateKeywords` 强制可转关键字
- `ExcludeKeywords` 排除块关键字：命中的块不参与排样，也不被移动（报在 `Result.Excluded` 里）

## 已知限制

1. 一个块里若含多个独立零件，只取最大轮廓并给出警告
2. `Polyline2d` / `Polyline3d` / `Region` / `Hatch` 不参与轮廓提取
3. 轮廓离散精度默认 0.1mm（按**弦高**控制，不是弦长）
4. 归并指纹按 0.01mm 取整，图纸有微小差异的「同款零件」会被当成不同品种
5. 同一零件以 90° 插入会被识别成两个品种（指纹基于世界坐标轮廓），不影响排样正确性
6. 排样**会修改块位置**，建议先备份图纸；不满意直接 `U` 撤销
7. 包围盒排样对填充率 < 97% 的异形件会浪费，目前只警告不优化
8. 多规格按「张数最少 → 板材总面积最小」择优，**不做成本最优**（各规格单价不同时需自己权衡，  
   结果里会同时给出「省料优先」的张数与面积供对比）
9. **文字关联靠几何推断**：文字必须落在块的包围盒内。放在块外一段距离的文字不会被关联，  
   会在警告里报"有 N 个文字没落在任何被选中的块里"
10. 文字如果是**在块定义内部**的，不需要关联（它本身随块移动），不占 `TextHandles`
